# Запуск: Supabase, Vercel і власний домен

Локальна розробка не змінюється — Docker і `pnpm dev` працюють як раніше.
Supabase і Vercel задіяні тільки на проді. GitHub лишається той самий.

Повна версія з поясненнями: артефакт «Запуск AIshka».

---

## 00 — Що завести

| Сервіс | Навіщо | Тариф |
|---|---|---|
| Supabase | Postgres замість локального Docker | безкоштовний |
| Vercel | хостинг застосунку | Hobby |
| Домен | адреса замість `*.vercel.app` | у реєстратора |

## 01 — Supabase

1. New project. Регіон — найближчий до аудиторії, не до себе.
2. **Пароль бази показується один раз.** Збережи одразу.
3. Project Settings → Database → Connection string. Потрібні ДВА рядки:

| Змінна | Який рядок | Хто користується |
|---|---|---|
| `DATABASE_URL` | Session pooler, `...pooler.supabase.com:5432` | застосунок |
| `DIRECT_URL` | Direct connection, `db.<ref>.supabase.co:5432` | лише міграції |

Через пул не працюють DDL і блокування Prisma. Пряме підключення вичерпає
ліміт з'єднань під безсерверними функціями. Тому обидва.

4. Створи `.env.production` у корені (він у `.gitignore`):

```
DATABASE_URL="<session pooler>"
DIRECT_URL="<direct connection>"
AUTH_JWT_SECRET="<новий: openssl rand -base64 48>"
NEXT_PUBLIC_APP_URL="https://<адреса від Vercel>"
BILLING_ENABLED="false"
```

`AUTH_JWT_SECRET` має відрізнятись від локального — інакше токен із твоєї
машини відкриє бойовий сайт.

## 02 — Наповнити базу

```
pnpm db:deploy:prod       # створює таблиці у Supabase
pnpm content:sync:prod    # заливає 172 уроки
```

Обидві читають `.env.production` через `DOTENV_CONFIG_PATH`, локальна база
не зачіпається.

**`migrate dev` на проді не запускати ніколи** — вона може запропонувати
скинути базу. `db:deploy:prod` викликає `migrate deploy`, яка лише застосовує
наявні міграції.

## 03 — Vercel

1. Add New → Project → репозиторій `AIshka`.
2. Framework Next.js визначиться сам, команди збірки не чіпати.
3. Environment Variables — ті самі п'ять змінних.
4. Deploy.

Змінні потрібні вже на етапі збірки: лендінг пре-рендериться і читає каталог
із бази. Без них сторінка збереться без карток курсів (навмисно не падає).

## 04 — Домен

1. Project → Settings → Domains. Додай і `example.com`, і `www.example.com`.
2. Vercel покаже точні DNS-записи — `A` для кореня, `CNAME` для `www`.
   Бери значення звідти: вони змінюються, тому в інструкції їх не фіксуємо.
3. Додай записи в панелі реєстратора.
4. Сертифікат Vercel випускає сам, купувати SSL не треба.
5. **Після того як домен запрацював** — зміни `NEXT_PUBLIC_APP_URL` на нього
   і натисни Redeploy, інакше посилання в листах ведуть на стару адресу.

## 05 — Перевірка

- [ ] Реєстрація створює акаунт і веде в онбординг
- [ ] Шість питань збирають план, видно пояснення першого юніта
- [ ] Урок відкривається, квіз і AI Task працюють, прогрес зараховується
- [ ] Academy показує всі полиці
- [ ] Вихід і повторний вхід зберігають прогрес

## 06 — Якщо не працює

| Симптом | Причина |
|---|---|
| Збірка падає на Prisma | немає `DATABASE_URL` у змінних Vercel |
| Міграції не застосовуються | у `DIRECT_URL` потрапив рядок пулу |
| Сайт відкривається, даних немає | у `DATABASE_URL` пряме підключення замість пулу |
| Каталог порожній | не виконано `content:sync:prod` |
| Домен не підхоплюється | DNS ще розходиться або записи не в тій зоні |

## Чого не робимо

**Авторизацію на Supabase Auth не переносимо.** У нас власна: argon2, JWT у
HttpOnly-cookie, ротація refresh-токенів. Supabase тут — просто Postgres.

**Медіа лишаються в репозиторії.** 3 МБ ілюстрацій Vercel віддає зі свого CDN
швидше за стороннє сховище. Воно знадобиться, коли з'явиться відео.
